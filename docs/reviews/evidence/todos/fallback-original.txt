发现 4 项需要修复：

1. **F1 / P1 — 完成旧动态会清空项目当前上下文。**
   `src/db.ts:958-965` 新增最新快照时仅复制 `status`，遗漏 `progress/blockers/nextSteps/decisions/tags`。完成一个旧动态，会使当前项目的其他阻塞和下一步从 `current` 消失。实测：最新状态为 `blocked`、阻塞为 `approval`，完成旧动态后得到 `blocked` 但 `blockers: []`。应保留最新项目快照的全部上下文，同时避免复制 `nextSteps` 再生成重复 Todo，或采用不替换项目当前快照的独立完成事件。

2. **F2 / P2 — HTTP 分块读取会损坏中文 Todo。**
   `src/server.ts:267-275` 对每个 Buffer 分别 `toString()`；UTF-8 字符跨块时会产生替换字符。实测将标题“中文”的第一个字符拆在两个 HTTP chunk 中，保存结果为“���文”。应按原始字节累计大小并拼接 Buffer 后统一解码，或使用 `StringDecoder`；补分块中文测试。

3. **F3 / P2 — Todo 页面刷新失败时错误不可见，保存流程仍报告成功。**
   `src/web/script.ts:66-69` 把所有加载错误只写入动态页的 `timelineContainer`，并吞掉异常；`mutate` 在 `389-393` 将刷新视为成功，创建表单随后清空输入。Todo 页面 `/api/todos` 失败时，用户只看到空白或旧列表，无法知道是否已保存，重试可能重复创建。应在全局 `actionError` 显示错误，区分“写入失败”和“写入成功但刷新失败”，不要把刷新失败当作正常完成。

4. **F4 / P2 — 项目筛选会覆盖用户明确选择的“不关联项目”。**
   `src/web/script.ts:383` 的 `projectOptions(select.value || activeProjectFilter)` 把空字符串当成未初始化。项目筛选下选择“不关联项目”后，任何触发 `render()` 的操作（搜索、切换语言、刷新或完成其他 Todo）都会重新选回项目；下一次新增将错误关联项目。应分开管理表单选择与筛选默认值，只在明确进入项目 Todo 页面时初始化默认项目。

另有一个较小的导航问题：从来源链接进入 `?entry=...` 后切到 Todo 页，任何写入后的 `fetchData()` 都会在 `src/web/script.ts:56-59` 强制切回动态页。建议仅首次读取深链接时导航，后续刷新保留当前页签。

其他检查：未发现新 Todo/旧 next-step 的幂等转换、源项目一致性、事务回滚或版本 3 导出恢复方面的直接错误。未执行完整测试套件和浏览器 UI 测试；上述 F1、F2 已独立动态复现，F3、F4 为完整事件调用链静态确认。
